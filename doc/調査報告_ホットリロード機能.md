# 調査報告：ホットリロード機能が動作しない問題

## 調査日時
2025年1月（推定）

## 調査目的
レイアウトファイルを変更するたびに `npm run dev` を手動実行する必要があり、ファイル変更の自動検知とリロード機能（Hot Module Replacement / Fast Refresh）が動作していない問題の原因を特定し、解決方法を提案する。

---

- **言語**: TypeScript
- **開発環境**: Windows 11
- **開発サーバー起動コマンド**: `npm run dev` → `next dev`
- **プロジェクトルート**: `C:\Users\katsu\Documents\workspace\show-spark`

## 問題の原因分析（推測）

### 原因1: Windows環境でのDockerボリュームマウント時のファイル監視の問題（可能性：高）

**事実**:
- DockerfileとREADMEにDockerを使った開発方法が記載されている
- Windows環境で開発している
- `next.config.ts`に「Docker + Windows でのホットリロード対応」というコメントがある

**推測**:
Windows環境でDockerコンテナにボリュームマウントする場合、以下の問題が発生することがある：
1. Windowsのファイルシステム（NTFS）とDockerコンテナ内のLinuxファイルシステムの違い
2. ファイル変更通知（inotify）がWindowsのボリュームマウント経由で正しく動作しない
3. Next.jsのデフォルトのファイル監視（watchpack）がファイル変更を検知できない

**確認方法**:
- 実際にDockerを使っているかどうか（`docker ps`で確認）
- Dockerを使っている場合、コンテナ内でファイル変更が検知されているか

### 原因2: Next.jsのファイル監視がポーリングモードになっていない（可能性：高）

**事実**:
- `WATCHPACK_POLLING` 環境変数が設定されていない
- `next.config.ts`にファイル監視の設定がない

**推測**:
Next.jsはデフォルトでファイルシステムの変更通知（inotify/FSEvents）を使用するが、Windows環境やDocker環境ではこれが動作しない場合がある。その場合、ポーリング（定期的にファイルをチェック）モードに切り替える必要がある。

### 原因3: Turbopackの設定が不完全（可能性：中）

**事実**:
- `next.config.ts`に `turbopack: {}` という空の設定がある
- コメントに「環境変数で制御」とあるが、具体的な環境変数は不明

**推測**:
Turbopackを使う場合、ファイル監視の設定が別途必要かもしれない。ただし、Next.js 16ではTurbopackは実験的機能であり、デフォルトでは使用されない。

---

## 解決方法の提案

### 解決方法1: 環境変数でポーリングモードを有効化（推奨）

**理由**:
- 最もシンプルで確実な方法
- Docker環境でもWindows環境でも動作する
- 設定変更が最小限

**実装方法**:

1. **環境変数ファイルを作成**
   - `frontend/.env.local` を作成
   - 以下の内容を追加：
   ```
   WATCHPACK_POLLING=true
   ```

2. **または、package.jsonのdevスクリプトを変更**
   ```json
   {
     "scripts": {
       "dev": "cross-env WATCHPACK_POLLING=true next dev"
     }
   }
   ```
   - `cross-env` パッケージが必要（Windows/Mac/Linuxで環境変数を統一して設定）

**メリット**:
- 設定が簡単
- Docker環境でもWindows環境でも動作する
- Next.jsの標準機能を使用

**デメリット**:
- ポーリングモードはCPU使用率が若干高くなる可能性がある（通常は問題にならない）

### 解決方法2: next.config.tsでwebpackのwatchOptionsを設定

**理由**:
- より細かい制御が可能
- ポーリング間隔を調整できる

**実装方法**:

`frontend/next.config.ts` を以下のように変更：

```typescript
import type { NextConfig } from "next";

const nextConfig: NextConfig = {
  // Docker + Windows でのホットリロード対応
  webpack: (config, { isServer }) => {
    if (!isServer) {
      config.watchOptions = {
        poll: 1000, // 1秒ごとにポーリング
        aggregateTimeout: 300, // 変更後300ms待ってから再コンパイル
      };
    }
    return config;
  },
  turbopack: {},
};

export default nextConfig;
```

**メリット**:
- ポーリング間隔を調整できる
- より細かい制御が可能

**デメリット**:
- Turbopackを使う場合はwebpackの設定が無視される可能性がある
- 設定がやや複雑

### 解決方法3: Dockerを使わずに直接起動（推奨度：低）

**理由**:
- Dockerを使わなければ、Windows環境でのファイル監視は通常問題なく動作する

**実装方法**:
- Dockerを使わず、`frontend/` ディレクトリで直接 `npm run dev` を実行

**メリット**:
- ファイル監視が確実に動作する
- 設定変更が不要

**デメリット**:
- Dockerを使っている理由（環境の統一など）があれば、それを失う
- 既存の開発フローを変更する必要がある

## 推奨される解決手順

### ステップ1: 現在の開発環境を確認

1. Dockerを使っているか確認
   ```powershell
   docker ps
   ```
   - コンテナが起動している場合は、Dockerを使っている

2. 開発サーバーの起動方法を確認
   - Dockerを使っている場合：`docker run` コマンドで起動している
   - Dockerを使っていない場合：`frontend/` ディレクトリで `npm run dev` を実行している

### ステップ2: 解決方法1を試す（最もシンプル）

1. `frontend/.env.local` ファイルを作成
2. 以下の内容を追加：
   ```
   WATCHPACK_POLLING=true
   ```
3. 開発サーバーを再起動
4. レイアウトファイルを変更して、自動リロードが動作するか確認

### ステップ3: 解決方法1で動作しない場合

1. `cross-env` パッケージをインストール
   ```powershell
   cd frontend
   npm install --save-dev cross-env
   ```
2. `frontend/package.json` のdevスクリプトを変更：
   ```json
   {
     "scripts": {
       "dev": "cross-env WATCHPACK_POLLING=true next dev"
     }
   }
   ```
3. 開発サーバーを再起動

### ステップ4: それでも動作しない場合

1. `frontend/next.config.ts` に解決方法2の設定を追加
2. 開発サーバーを再起動

## まとめ

### 事実
- Next.js 16.0.10を使用
- Windows 11環境
- Dockerを使った開発環境の可能性がある
- ファイル監視関連の設定が不足している

### 推測される原因
1. Windows環境でのDockerボリュームマウント時のファイル監視の問題
2. Next.jsのファイル監視がポーリングモードになっていない

### 推奨される解決方法
1. **最優先**: `WATCHPACK_POLLING=true` 環境変数を設定（解決方法1）
2. **次点**: `next.config.ts`でwebpackのwatchOptionsを設定（解決方法2）
3. **最終手段**: Dockerを使わずに直接起動（解決方法3）

### 次のステップ
1. 現在の開発環境（Docker使用有無）を確認
2. 解決方法1を試す
3. 動作を確認し、必要に応じて解決方法2を試す
